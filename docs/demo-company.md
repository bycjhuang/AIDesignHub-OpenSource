# 三项目、八成员演示公司

## 打开与数据隔离

- 双击项目目录内的 `启动-3项目8人演示.cmd`，或者 `node scripts/start.cjs --demo-company`。
- 普通启动仍打开原有数据。演示默认存入当前 Windows 用户应用数据下的 `demo-company-v1`；不复制或修改 `design-workbench-v1`。
- 若开发环境指定 `AIDESIGNHUB_DATA_DIR`，演示库会创建在该目录的 `demo-company-v1` 子目录，而不是覆盖其 `store.json`。
- 首次初始化后保留练习结果。重复启动不会重新播种、重置任务或清空审批。
- 这些是虚构业务数据，不是实际人员账号、真实回款记录或已完成的项目验收。
- 正常与演示模式使用同一套代码，左下角模型入口与自动连接助手同时生效。本机模型设置和受支持启动模板配对共用；项目资料、成员权限、MCP 项目授权、模型任务验证及成果仍各自隔离。

## 三个项目

| 项目 | 当前阶段 | 可体验的情景 |
| --- | --- | --- |
| 江湾文化商业中心 | 概念设计，第 2 轮 | 入口雨棚口头变更，比较方案、澄清边界、负责人审批 |
| 云栖庭院住宅社区 | 方案深化 | BIM 碰撞与车库净高问题、校审受阻、成果提交 |
| 青岚地方文化中心 | 项目前期研究 | 任务书缺项、文化线索、现场踏勘与需求确认 |

## 八张身份卡

| 成员 | 组织职责 | 项目权限类别 |
| --- | --- | --- |
| 许知行 | 公司负责人 | 公司负责人，可审批 |
| 林澜 | 项目经理 | 项目经理，可审批 |
| 周远 | 设计总监 | 设计总监 |
| 陈设计 | 建筑设计师 | 项目设计师 |
| 沈亦舟 | BIM 负责人 | 项目设计师 |
| 顾青禾 | 景观与室内设计师 | 项目设计师 |
| 赵工 | 校审负责人 | 校审负责人 |
| 方敏 | 经营财务 | 经营 / 财务 |

八位公司成员分别通过同一个 `personId` 关联三个项目，各项目拥有不同 `memberId`。这是八个人、二十四条项目成员关系，不是二十四位员工。组织职责与权限类别分开：BIM 和景观设计师有各自任务，但不因此获得负责人审批权。

## 建议体验顺序

1. 打开「团队与设置」，查看三项目参与矩阵、职责和已登记任务。
2. 点左下角身份卡 → 陈设计 → 当前商业项目，查看自己的设计工作及「项目上下文」里的待审批事项；此时只可查看，不能审批。
3. 再切为林澜，打开同一候选；核对内容，勾选确认并审批。审批才会写入该演示项目，留下更新回执。
4. 切为沈亦舟进入住宅项目，查看 BIM 协同任务与受阻事项；确认上下文和聊天不会带入商业项目。
5. 切为方敏，查看合同条件和回款节点；切为许知行，查看跨项目配置和项目风险。

审批测试是真实业务逻辑在隔离演示库内执行；群聊的 `@DesignHub`、语音、截图和聊天内角色编辑仍是前端 Demo。它们不会变成企业登录，不会向其他电脑发送消息。打开演示不会调用模型；保存本机模型后可自动运行连接助手（会调用内置模型规划配对、启动已发现入口检查协议），正式任务仍需另行发起和授权。
