# Agent 协作：聊天优先界面

## 用户要求

原界面的连接参数、协议、可执行文件路径、JSON 参数、MCP 授权过于复杂。默认应是聊天窗口，输入框下选择桌面 Agent，类似聊天产品的模型选择器；配置在用户主动点击时才出现。

## 实现结构

- `agent-chat-ui.js` / `agent-chat.css`：对话消息、Agent 选择、输入框、追问、执行进度、人工验收与历史恢复。
- `agent-ui.js`：原配置、发现、测试、MCP 和详细运行记录保留，改由原生 dialog 按需打开；MCP 再单独折叠。
- `backend/agent-hub.cjs`：本机 `sendChat` 创建持久化会话，每轮复用真实 job/run；不新增外部 MCP 聊天写入工具。
- `preload.cjs` / `electron-main.cjs`：窄 IPC 入口 `agentSendChat`，默认不启动项目工具服务；明确勾选时才挂载既有只读工具。

## 保留的边界

1. 聊天是固定输入的任务执行入口，不接管外部桌面软件的私有聊天窗口。CLI / ACP / HTTP 与 MCP 入站仍然区分。
2. 默认不开放项目知识检索；工具授权逐轮明确勾选，不从历史继承。外部执行器仍保有自己的权限，不能宣称已做系统沙箱。
3. 历史仅来自当前项目的当前会话，最多 12 条、48 KiB，每条最多 16 KiB。转发给另一 Agent 需要明确确认；长历史的省略会显示提示。
4. 每轮有请求 ID，重试不重复派单；同会话在执行中不接受第二个任务。模型输出停在待人工验收，追问不等于批准。
5. 消息作为纯文本显示，网页片段或模型 HTML 不执行。输入法组词回车不误发。
6. 密钥与敏感配置在设置关闭、Esc、MCP 折叠、离页时清除；异步创建/模板响应仍需通过可见性及版本检查。
7. 后台状态带项目标识；项目切换时不把旧请求的结果写进新项目聊天界面。派单已确认但刷新失败时，提示查看历史，不谎称草稿仍在。
