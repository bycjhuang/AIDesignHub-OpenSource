# 案例调研与 Agent 协作修复

## 问题与结果

URL 误进名称调研、名称默认本机助手选项残留到链接模式，以及失联网关未经检查直接派单，会分别造成错误模型入口或执行失败。现按提交内容再次识别链接，兼容旧失败 URL 卡片；页面、图片归档和 Agent 结果分别记录，不用一次 Agent 失败抹掉成功读取的资料。来源字段仍需人工核实，失败和格式错误不作为已完成调研。

图片采集改为整篇有界管道：最多 600 个候选，正文和来源落盘；微信 qpic 先尝试 `/0`，失败退回公开页面版本并记录；支持 PNG、JPEG、静态 WebP 和经过结构验证的 GIF。失败项重试后继续归档，重采失败保留旧正文及原图。后台案例归档排队等待采集槽位，取消和关闭可以退出。

浏览器验证阻止直接读取时，原生文件选择器可导入用户保存的 HTML，提取正文、公开图片地址以及同名 `_files`／`.files` 目录下的本地图片。导入不执行脚本，不接受渲染层通用文件路径；本地图片范围、软链接、体积及格式均校验。导出包含 `article.txt`、`article.json`、原图和 `sources.json`。

## 本机 OpenClaw

已核查网关缺失 `gateway.mode`，其自身因此拒绝启动。在同目录备份原配置后，通过官方 CLI 仅补 `gateway.mode=local`，保持原端口 18790、模型和账户不变。网关仅在本机回环地址监听。CLI 健康检查成功，新会话固定文字真实执行返回“AIDesignHub 连接测试通过。”，该次执行不带 Hub 项目资料或项目工具授权。未自动重放之前的失败任务。

这验证了网关、真实派单和结果回传，不代表已经验证真实建筑案例的联网研究质量。用户提供的微信文章实际返回访问验证页，不能宣称已经下载到该篇所有图片；可经用户正常浏览后保存完整网页并导入。
