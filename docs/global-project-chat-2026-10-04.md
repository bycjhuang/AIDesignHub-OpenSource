# AIDesignHub 0.3.0：全局项目沟通与内置助手

## 产品边界

项目记忆、成员身份、任务与确认记录留在 Hub。内置 AI 帮助理解和整理资料；外部桌面 Agent 是可替换执行器，只在“Agent 协作”中启动。二者不是同一会话，不自动复制聊天或扩大权限。

## 操作路径

1. 左上角选择项目。可创建独立本机项目，不复制原项目内容。
2. 点击“聊天与项目 AI”，右侧打开全局面板；左侧“项目沟通”进入同一个面板的群聊频道。
3. 切换页面，面板保持打开，标签与“本次发送范围”更新。切换页面或项目会撤销本次模型授权勾选。
4. 普通频道消息只保存/同步。向“项目助手”发问，或在群聊中 `@DesignHub`，再勾选“允许本次使用内置 AI”，才调用已配置模型。邮箱地址或更长单词不作为召唤。
5. AI 提出事项后，点击“查看建议 · 核对后写入”。可修改责任人、阶段、任务和风险；明确确认后，业务记录与审计一起落盘。
6. 不调用 AI 时，可使用“整理为待确认事项”，保存原文并人工添加事项。
7. 聊天“成员”管理本项目身份；“⋯”中查看历史事项、切换本机身份、进入同步设置。

## 页面上下文的数据来源

| 页面 | 实际提供给内置助手的内容 | 不做什么 |
| --- | --- | --- |
| 知识中心 | 当前项目已导入资料与本次问题命中的摘录、来源定位 | 不读全盘，不凭空生成规范依据 |
| 案例与素材 | 当前项目保存的案例字段与摘录 | 普通问答不自动联网采集或启动桌面 Agent |
| 设计流程、进度与风险 | 当前登记任务、风险与人工设定阶段 | 不从文件数量推断完成率 |
| 项目文件 | 已导入资料的名称与状态 | 不自动读取原文件、模型或发送本地路径 |
| 技能中心 | 已发布技能的描述与版本 | 不把技能正文当系统指令执行 |
| 合同与回款 | 项目实际负责人/财务角色可提供登记信息 | 展示角色切换不提权，模型不确认收款 |
| 团队看板 | 当前项目成员与任务数 | 不将其他项目人员明细自动发给模型 |
| Agent 协作 | 内置面板只解释项目资料 | 只有独立执行区派发外部 Agent |

每次请求附有 bounded 项目摘要（当前阶段、有效决定、登记任务与风险）；页级资料另列，用户可以先查看发送范围。群聊历史和附件不默认传给模型。助手短期对话历史只使用同项目、同成员、同频道、同页面已完成的模型对话。

## 项目切换与记录

- 每个项目有独立频道与 canonical 助手频道 `hub_assistant_<projectId>`。
- 同一人的多项目关系依赖明确 `personId`，旧资料不按姓名猜测合并。
- 旧请求在原项目结束，不覆盖当前项目输入、历史、案例缓存或执行器表单。
- 成员角色修改需实际项目经理/负责人，校验旧角色以防并发覆盖，并记录审计。
- 当前本机身份选择是原型管理能力，不是企业登录认证。数据库及同步房间仍须受信任使用。
- 团队同步只合并指定项目，不清空本机其他项目。同步期间不允许切换项目；先断开同步。

## 当前限制

- 内置模型兼容配置继承 0.2.0：DeepSeek、百炼按量、自定义兼容接口；未配置时仍可聊天留档与人工整理。API 密钥由系统加密，不进项目库或 Git。
- 尚无截图 OCR、语音、任意附件模型理解。旧附件记录仍保存，但新统一输入框目前以文字为主。
- 原有局域网同步继续保留；内置助手与正式事项整理目前在项目主机处理，远端客户端只发普通群聊。跨终端新提醒仍是待同步记录，不冒充已送达。
- 团队负荷使用实际项目数、未完成任务数、逾期任务数；没有工时数据时不生成百分比，也不自动作为绩效结论。
- 此版为本地源码运行版；不等于已制作、签名和验收的新公开安装包。

## 验证约定

单元测试检查存储、上下文边界、授权、请求幂等、模型错误与项目隔离。Electron 隔离烟测通过真实 preload/IPC 和渲染层检查操作链路；模型为合成替身，不使用用户密钥，不消耗额度，不代表真实供应商已联通。

本轮实测：286 项本地测试全部通过；全局聊天 25 项桌面断言全部通过，包含 7 次合成模型回复；原有项目事项、技能、案例、执行器闭环回归通过。最终渲染错误列表为空。隔离测试库与截图不进入 Git，也不混入真实项目资料。
