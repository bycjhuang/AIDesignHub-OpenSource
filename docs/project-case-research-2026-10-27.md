# 项目案例调研与案例研究 PPT（2026-10-27）

## 操作

1. 进入「案例与素材库 → 分派项目调研」，确认右侧项目名称。
2. 填写研究方向、案例数，可指定原始链接。选择已经配置的主动执行 Agent；该 Agent 需有可用模型与联网检索能力。
3. 点击「分派并开始调研」。勾选项目背景时，会带上经过现有项目上下文规则过滤的背景、任务及已确认决策。派单会使用所选 Agent 的模型额度。
4. 研究结束后查看任务详情、全部来源、项目参考点及归档缺口。案例写回当前项目案例库，符合条件的图片进入本机项目素材库。
5. 点击「生成案例分析页」保存可离线查看的单页 HTML，或点击「生成案例研究 PPT」保存可编辑 PPTX。两者包含项目条件、案例、参考点、本地图片、实际像素尺寸、来源链接和未完成事项；生成时不再联网或调用模型。
6. 「重新核验与补图」复用原 Agent 成果重新读取来源和归档图片，不再调用模型；「重新调研」会建立新的 Agent 运行。导出优先为各案例均衡选择最多 6 张代表图，全部已归档图片仍可在项目素材库查看与导出。

## 已授权的演示项目背景

用户明确授权为现有项目编制基础信息用于案例对标；数据存入项目 `researchProfile`，保留 `isSynthetic: true` 和“非实际项目指标”标记。江湾设为中型滨水文化商业街区，用地 42,000㎡、地上 75,600㎡、地下 26,000㎡、总建面 101,600㎡、容积率 1.8、最高 36m。另为云栖庭院住宅社区、青岚地方文化中心按其类型补齐定位、规模、目标与待核实条件。默认工作区与三项目演示工作区均已补齐，写入前保存原 store 备份，已有 profile 不覆盖。

显式维护命令为 `node scripts/seed-research-profiles.cjs --data-dir <现有数据绝对路径>`；先关闭使用该目录的 Hub。真实调研 CLI 为 `node scripts/run-project-research.cjs --data-dir <现有数据绝对路径> --output-dir <导出绝对路径> --agent=deepseek`，使用现有执行器与独占服务锁，不生成模型凭据。

## 图片与证据口径

- 优先设计专业来源：ArchDaily、Archigo、谷德、金盘网，允许补充设计方官网、公众号及小红书。
- Agent 搜索结果不能直接当作已阅读的页面。后端再次读取公开链接，分别保存可访问性、正文证据及失败原因。无法取得的页面仍保留链接供人工检查。
- 图片优先取文章正文容器内候选。推荐、广告、头像等区域排除；区域不明时，只接受 Agent 明确指定且确实出现在该页面的图片链接。
- 默认高清门槛为实测长边至少 1600 px、短边至少 600 px；下载后校验真实图片字节和尺寸，按内容哈希去重，同时保留多页面来源。
- 这里的自动相关性规则是正文结构和 Agent 选图，不是对每张下载图片做本机视觉语义识别。混入正文的其他项目图仍需要人工复核。
- “原图”指来源页面实际公开的可获取版本。不能承诺存在未公开的摄影母版；不以放大、改 URL 或更名冒充高清原图。
- 登录、验证码、反爬、过期签名、页面仅公开缩略图、网页未暴露图片等会导致部分完成。不会以搜索摘要冒充文章全文，也不会自动处理验证码。

## 实现与数据边界

- `backend/project-research.cjs`：任务记录、派单、Agent 结构化成果、多来源核验、案例归档及项目参考点。
- `backend/research-images.cjs`：多页面图片筛选与归档，复用原图素材服务。
- `backend/research-presentation.cjs`：确定性本地 PPTX 导出。
- `backend/research-analysis-page.cjs`：含内嵌本地图的离线案例分析页。
- `backend/project-research-profiles.cjs`：演示项目基础信息与上下文白名单。
- `backend/project-research-ipc.cjs`：只允许主窗口、当前项目和不透明记录编号；图片路径只从后端归档服务取得。
- `project-research-ui.js` / `project-research.css`：案例页任务入口、进度、来源与导出。
- 正式项目任务、决策和审批不由案例研究自动确认。现有包名、密钥存储位置及渲染层 Node 隔离不变。
