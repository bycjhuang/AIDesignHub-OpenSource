## 使用顺序

1. 在 `00_项目控制/项目登记.json` 填真实项目信息和授权角色，确认后才将状态改为有效。
2. 确认 `交付基线.json` 的实际成果、责任人、期限和检查/验收要求；空清单不代表工作已完成。
3. 收件先登记来源与拟分类；经确认后由 Hub 或授权档案管理员归入输入/商务/沟通区域。工作文件和引用依赖不要盲目移动。
4. 人与 Agent 在任务工作区产出；用 `成果提交单.template.json` 提交候选成果。
5. 管理员核对文件和审核依据，再提交正式版本并追加台账；未来这一步由 Hub 归档服务实现。本模板与 Skill 不能自行实现权限隔离或事务提交。

## 台账原则

JSON 中的 null 和空数组表示尚未提供，不是默认确认、金额为零或完成率为零。CSV 目前只有表头。字段中的路径仅为引用，跨机器时需要映射；文件快照和事件记录才是审计依据。

原生模型与外部参照、贴图、链接文件应保持依赖关系；归档包应能复核打开。权限、版本、命名和保留期限见上级管理规约，不能仅靠目录名称实施。
