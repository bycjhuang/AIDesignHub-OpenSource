# AIDesignHub 设计管理规则包

版本：0.1 · 2026-10-04 · **共创草案，尚未成为应用的运行规则**。

这里约定设计公司的项目如何接收、组织资料、安排工作、提交成果、验收归档和判断进度。它是 AIDesignHub 的业务依据，不是一个独立聊天产品，也不是已部署的 BIM 插件。

## 从这里开始

1. 阅读 [设计管理运行规约](01-设计管理运行规约.md)，确认职责、阶段、证据和归档边界。
2. 阅读 [人机协作改造说明](../docs/human-ai-hub-2026-10-04.md)。CAD/BIM 深度读取不是本轮前置条件，阶段由人判断。
3. 打开 [项目目录模板](project-template/使用说明.md)。目前仅有部分模板与空台账，未创建完整目录树，也未移动真实项目文件。
4. 下列四个方法包是后续共创计划，尚未编写完成、安装或接入正式归档服务。应用中的技能中心已可发布成员贡献的方法文本，但不能据此认为这四份方法已交付。

| Skill | 使用时机 | 主要输出 |
|---|---|---|
| 资料接收与分类（待共创） | 新项目资料到达、补充资料到达 | 收件清单、分类建议、缺项和冲突清单 |
| 阶段工作与派单（待共创） | 建立或变更阶段计划、向 Agent 交接任务 | 阶段交付清单、任务上下文包、验收要求 |
| 成果提交与归档交接（待共创） | 人或 Agent 提交成果 | 成果清单、验证证据、归档申请，不代替正式归档服务 |
| 进度与风险复核（待共创） | 人员更新项目状态 | 待办与风险整理建议，不让 AI 猜测阶段 |

## 完成与未完成的边界

- 此目录已保存：部分目录/台账模板与管理规约草案。
- 此目录尚未交付：四个专属方法包、完整模板验证、目录监听、模型解析插件、归档事务/权限隔离、合同条款审核界面。
- 应用已实现的人工作业与项目助手闭环，见上方改造记录；它不是自动推算设计进度的系统。
- Skill 能指导 Agent，不会凭一份 Markdown 自动获得读写权限或软件接口。首次实际项目试跑时，必须明确项目、资料范围、执行工具和输出位置。
- 本包不宣称符合或认证通过 ISO 19650；借鉴其信息交付和共同数据环境理念，具体规则仍需与公司的项目和合同约定共同确认。

## 建议的第一次共创

用一个已结束或可脱敏的项目，仅选一个阶段进行回放：资料接收 → 明确三到五项真实交付要求 → 提交一版成果 → 一次退回修改 → 一次确认 → 查看状态如何变化。先确认规则能解释真实工作，再接入软件自动化。不要用演示进度作为验收结果。

待确认的公司级选择：先覆盖商业还是住宅；实际使用哪些创作软件；阶段命名和交付清单；内部审核/业主确认角色；现有目录如何映射；允许调用云端模型的资料范围。
